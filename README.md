# 配送员 · 批量视频上传（分发包说明）

把本地视频文件夹按名称匹配到快手**磁力金牛**广告主账户 ID，再批量上传到各账户的视频库。

- 同一账户下的所有文件夹**合并成一批**上传（超 100 个自动分批）
- 上传前按清单**自动打标签**（弹窗里没有的标签会自动新建）
- 单个素材失败不影响同批其它素材，失败的会整理成**完整名称 + 失败原因**的 Markdown 表格
- 每个账户开**独立标签页**且跑完不关，方便事后核对
- 走 Chrome 调试端口直连，**没有 512 MB 单文件上限**，也不需要分块

---

## 一、三步上手（换新电脑必做）

### 1. 装依赖

```bash
pip install websocket-client openpyxl
```

### 2. 用调试端口启动 Chrome

**先把 Chrome 完全退出**（含右下角托盘），再执行：

```bash
chrome.exe --remote-debugging-port=9222 --user-data-dir="C:\Users\<你的用户名>\AppData\Local\Google\Chrome\User Data"
```

用**原 profile** 启动才能带上登录态。启动后在 Chrome 里登录磁力金牛，  
并打开任意一个账户的视频库页面。

> 建议把这条命令存成桌面 `启动Chrome调试.bat`，以后双击即可。

### 3. 配置本机路径

把 `config.example.json` 复制一份改名 `config.json`，改成你机器上的实际路径：

```json
{
  "videoRoot": "D:/视频",
  "xlsxPath": "C:/Users/你的用户名/Desktop/账户ID.xlsx",
  "chromePort": 9222
}
```

- `videoRoot`：所有视频文件夹的上级目录
- `xlsxPath`：账户清单表格（见下）
- 不建 config.json 也能跑，会用代码里的默认值（`D:/视频` + 桌面 `账户ID.xlsx`）

### 4. 自检（确认环境没问题）

```bash
python scripts/setup_check.py
```

全绿就可以开工。缺依赖时加 `--fix` 自动装：

```bash
python scripts/setup_check.py --fix
```

## 二、账户清单表格格式

一行一个项目，前三列必须是：

| 项目名称   | 账户ID           | 标签      |
| ------ | -------------- | ------- |
| 断痔膏-痔疮 | 12345678(仅供参考) | 新素材     |
| 十二味草本枕 | 23456789(仅供参考) | 9.9     |
| 螺狮粉    | 12345678(仅供参考) | 9.9、新素材 |

- **账户ID 必须是文本格式**，否则会被 Excel 存成 `12345678.0` 拼进 URL 报错
- **标签**可留空；多标签用逗号 / 顿号 / 分号分隔；同一账户多行会自动合并去重
- 标签会透传成纯文本，`9.9` 这种小数不会被丢精度

## 三、视频文件夹命名

文件夹名里要包含项目名称里的关键词，脚本按词元做正向/反向包含匹配。例如：

```
D:/视频/
├── 2026年10月27日-张三-断痔膏-1/        ← 命中「断痔膏-痔疮」
├── 2026年10月27日-张三-草本枕-2/        ← 反向命中「十二味草本枕」
└── 2026年10月27日-张三-螺狮粉-1/        ← 命中「螺狮粉」
```

匹配是**双向包含**：文件夹里的词是项目名的子串也算命中（简称 ⊂ 全称）。  
默认递归子目录，取 `.mp4`（可用 `--ext` 改）。

## 四、跑起来

### 第一步：生成匹配清单

```bash
python scripts/match_accounts.py
```

输出 `配送员_匹配清单.csv` + `.md`，并列出「未匹配文件夹」和「没有文件夹的项目」。

```bash
# 也可指定路径
python scripts/match_accounts.py --xlsx "账户ID.xlsx" --video-root "D:/视频" --out "清单.csv"
```

> ⚠️ **拿到清单先人工确认再上传**，尤其是「反向包含」命中的和「一个账户被多个文件夹命中」的。

### 第二步：试运行（强烈建议）

```bash
python scripts/batch_upload.py --map "配送员_匹配清单.csv" --aggregate --dry-run
```

只会注入再取消，不真正入库；同时会**校验账户ID 是否有效**——  
出现 `ACCOUNT_MISMATCH` 就说明这个 ID 失效或当前登录号没权限，去核对账户表。

### 第三步：正式上传

```bash
python scripts/batch_upload.py --map "配送员_匹配清单.csv" --aggregate
```

**大批量（100+ 个）务必后台跑 + 日志重定向**：

```bash
# Linux / macOS / Git Bash
python scripts/batch_upload.py --map "清单.csv" --aggregate > 上传日志.txt 2>&1 &
```

原因：前台 shell 常有 600 秒上限，超时会被 SIGTERM 掐掉；输出走管道是全缓冲，  
进程被杀时日志一个字都不剩，看起来像啥也没干（其实可能已经传完）。

常用附加参数：

| 参数                         | 作用                 |
| -------------------------- | ------------------ |
| `--only-account "123,456"` | 只跑指定账户             |
| `--only-folder "断痔膏"`      | 只跑指定文件夹            |
| `--skip-folder "螺狮粉"`      | 跳过指定文件夹            |
| `--no-recursive`           | 只扫文件夹顶层            |
| `--dedupe`                 | 上传前翻页扫库去重（慢，见已知限制） |
| `--port 9223`              | 换调试端口              |

产出 `上传结果_<时间戳>.csv` 和（有失败时）`失败素材_<时间戳>.md`。

## 五、结果怎么看

结果 CSV 每行一个文件夹：

| 字段                | 含义                                                         |
| ----------------- | ---------------------------------------------------------- |
| `status`          | `UPLOADED` / `DRYRUN` / `ACCOUNT_MISMATCH` / `RUNNING`(中断) |
| `ok_n` / `fail_n` | 该文件夹自己的成功 / 失败数（聚合时按文件归属摊派）                                |
| `account_name`    | 页面上回读到的账户名，**用于核对有没有传错账户**                                 |
| `failed_files`    | 失败素材（完整名），分号分隔                                             |
| `failed_reason`   | 对应失败原因，与 `failed_files` 一一对应                               |

`UPLOADED` 只表示这一批跑完了，**不等于全部传上去了**——真实结果看 `ok_n`/`fail_n`。

失败原因按这两类处理：

- `视频宽高比需满足条件` / `视频上传失败，未取得视频ID` → **素材本身不合规，重剪重导**  
  （最常见：1080×1924 差 4px，平台要求 1080×1920）
- `不能上传内容重复的相同视频` → 库里已有，正常，不用重传

## 六、常见问题

| 现象                                                 | 原因 / 处理                                                                 |
| -------------------------------------------------- | ----------------------------------------------------------------------- |
| `ModuleNotFoundError: No module named 'websocket'` | 漏装依赖，`pip install websocket-client openpyxl`                            |
| 连不上 `127.0.0.1:9222`                               | Chrome 没带调试端口启动，或已有 Chrome 进程占用 profile。完全退出 Chrome 后重开                 |
| 「视频库未就绪」                                           | 标签页是 `jinfu.e.kuaishou.com`（服务商后台）。上传必须在 `niu.e.kuaishou.com`（投放后台）页面里做 |
| `ACCOUNT_MISMATCH`                                 | 页面停在别的账户上。该 ID 失效或当前号无权限，重跑无效，去核对账户表                                    |
| 跑一半被掐、日志空的                                         | 前台 600s 超时。改后台跑 + 重定向，或用 `--dedupe` 补跑（已传的会被平台以重复拒，无害）                  |
| 一堆「重复视频」失败                                         | 用了 `--dedupe` 但翻页采集不全（已知限制），或之前已经传过                                     |
| 时长很久没动静                                            | 正常。100 个 / 3.4 GB 约 7–10 分钟，吞吐 6–8 MB/s                                 |

## 七、已知限制

1. **去重扫描会漏判**：列表页每页 10 条里只有 8 条名字读得到，105 个只能采到 85 个。  
   `--dedupe` 因此默认关闭。真需要就人工先确认库内没有。
2. **不做并发**：实测多账户同时传吞吐腰斩（8.45 → 3.3~4.4 MB/s）且失败卡片会抓串。  
   已定案串行，别再试。
3. **平台限制**：单次 ≤100 个、单文件 <500 MB。
